# Tuman Lake ZBT readiness audit

Дата: 2026-06-09

Репозиторий: `GaggerStudioIL/TumanLake`
Ветка: `master`
Версия: `v0.1.0-beta.2`

## Scope

Проверялся первый закрытый beta-маршрут без расширения игры новыми системами:

`запуск -> intro/main -> Озеро Агамим -> HUD -> выбор/проверка снасти -> заброс -> поплавок на воде -> поклёвка -> вываживание -> popup рыбы -> садок -> Рыбная гавань -> продажа -> сохранение/перезапуск`.

Проверка выполнена как code/readiness audit плюс локальный Godot smoke-запуск проекта. Физическая установка APK на Android-устройство и ручной tap-through всего маршрута в этом проходе не выполнялись.

## Проверки

- `master` синхронизирован с `origin/master`; рабочее дерево перед отчётом было чистым.
- Версия в `scripts/core/GameVersion.gd`: `0.1.0-beta.2`, дата `2026-06-09`.
- Beta flags в `scripts/core/BuildConfig.gd`: `IS_BETA_BUILD=true`, debug/verbose/spinning отключены.
- Android export preset указывает `build/TumanLake_0.1.0-beta.2_2026-06-09.apk`, `version/name="0.1.0-beta.2"`, `version/code=102`.
- Godot smoke: `Godot_v4.6.2... --display-driver windows --rendering-driver opengl3 --path . --quit-after 2` завершился с exit code `0`, без `SCRIPT ERROR`.

## A) Что уже работает

- Стартовый маршрут сцены корректный: проект стартует через `scenes/intro/IntroCinematic.tscn`, затем переходит в `scenes/main/Main.tscn`.
- Runtime-ссылок на старую пустую `scenes/fishing/LakeScene.tscn` не найдено; файл отсутствует, в tracked runtime-путях ошибочных переходов нет.
- Day/night стабилизирован для beta: видимый диск солнца скрыт, но дневное свечение и отражение остаются; луна позиционируется по ночной дуге и ограничивается sky/horizon-зоной; ночь тонируется, но не должна становиться полностью чёрной.
- HUD рассчитан от базового 960x540: ловля, садок, инвентарь, карта, энциклопедия, системное меню и текущая снасть имеют явное позиционирование и `MOUSE_FILTER_STOP`.
- Модальные окна перенесены в modal layer; full-screen `ModalInputBlocker` блокирует клики под открытыми окнами.
- Поплавочная снасть beta полная: обязательные слоты `rod`, `line`, `leader`, `float`, `hook`, `bait`; дефолтный игрок получает стартовую удочку, леску, поводок, поплавок, крючок и червей.
- Старые сохранения со снастью мержатся с дефолтом; поводок и поплавок страхуются fallback-компонентами.
- Заброс проходит через cast visual, landing target зажимается в water/cast area, после успешного заброса включается `set_float_in_water(true)`.
- Ожидание поклёвки, подсечка, вываживание, победа/провал и catch popup связаны через `FishingManager` signals; после результата UI обновляется и сохраняется.
- Inventory v2 использует отдельную details panel со scroll/clip, autowrap и компактной раскладкой под 960x540.
- Магазин работает без пагинации: pager скрыт, список строится в ScrollContainer; категории beta scope включают снасти/наживки, расходники скрыты.
- Покупка предмета списывает деньги, добавляет предмет в `PlayerData.owned_items`, при снасти обновляет текущий слот и сохраняет игру.
- Рыбная гавань продаёт через `SalesService`: рыба удаляется из садка, деньги начисляются в `PlayerData.money`, после успешной продажи вызывается `SaveManager.save_game()`.
- Save/load сохраняет деньги, опыт, уровень, инвентарь, садок, снасть, текущий водоём/точку, глубину и время.
- Старые/битые location данные безопасно нормализуются: недоступный водоём возвращает игрока на `agamin_lake`, неверная/legacy точка заменяется primary spot или `old_oak_pier`.

## B) Что не работает / что не подтверждено

- Автоматический headless route script через `--script` в этом окружении падает до пользовательских логов Godot; это не воспроизведено обычным запуском проекта и не классифицировано как игровой blocker.
- В Godot smoke остаются существующие warnings про anchors и утечки RID/Texture на выходе при `--quit-after`. Они не блокируют запуск Main-сцены и APK export, но засоряют лог.
- Полный маршрут на реальном Android-устройстве в этом проходе не был протапан вручную. Перед раздачей тестерам стоит один раз пройти install smoke на телефоне.
- Видимый диск солнца отсутствует намеренно для beta. Если нужен именно диск солнца как часть финальной композиции, это deferred visual work, не blocker.

## C) Что исправлено / подтверждено после исправлений beta.2

- Версия и Android export preset уже приведены к `v0.1.0-beta.2`.
- Пустая `LakeScene` удалена из runtime-пути, стартовый маршрут идёт через intro -> Main.
- День/ночь приведены к beta-safe варианту: солнце не конфликтует с фоном, используются glow/reflection; луна остаётся в читаемой области.
- Shop/Harbor убраны с основного HUD и доступны через карту водоёма; садок оставлен viewer-ом улова, продажа вынесена в Рыбную гавань.
- HUD текущей снасти, быстрые кнопки и modal blocker уже приведены к текущему beta flow.
- Расходники и out-of-scope spinning-предметы скрыты в beta scope; `ENABLE_SPINNING_FEATURES=false`.
- Tester guide, beta checklist и build notes уже присутствуют в `docs`.
- В рамках этого прохода добавлен данный ZBT readiness report; игровых систем и нового контента не добавлялось.

## D) Оставшиеся blocker-баги

Новых blocker-багов по коду и локальному smoke-запуску не найдено.

Не считаются blocker-ами, но остаются рисками перед внешней раздачей:

- нужен ручной Android install smoke;
- желательно в будущем почистить anchor warnings/leak-on-exit noise;
- видимый солнечный диск отложен до отдельного визуального решения.

## E) Можно ли давать билд ЗБТ

YES для закрытого beta build.

Рекомендация: перед отправкой тестерам выполнить один короткий ручной проход на Android: установка APK -> intro/Main -> один заброс -> поклёвка/бой -> оставить рыбу -> открыть Рыбную гавань -> продать -> закрыть и запустить игру снова.
